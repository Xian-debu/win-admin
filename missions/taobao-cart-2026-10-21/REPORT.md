## 2. 怎么采的（纯 GUI 驱动，无接口抓包）

1. `wwin focus` 把 Edge（hwnd 593116）提到前台；`ctrl+l` 输入 `https://cart.taobao.com/cart.htm` 回车（坐标点导航链接点偏过，改走 URL 更稳）。
2. `sweep-page.sh`：每轮 `ctrl+a` → `ctrl+c` → `wclip get` 存 `round-NN.txt` → `escape` → `pagedown`。淘宝购物车是滚动懒加载，单次复制只有 8 条左右，靠 25 轮累积才拿到全部渲染文本（`raw/p1c/round-25.txt`，62 个支付行 + 底部「猜你喜欢」标记）。
3. 50% 缩放后 `ctrl+home`，逐屏截 12 张（`shots/s01–s12.png`）做视觉第二来源。
4. `parse-cart.py` 解析文本 → `parsed-v3.json`；`build-xlsx.py` 生成 xlsx。

## 3. 解析规则（踩过的坑都写进代码注释）

页面文本每行条目模板：

```
店铺名 / 款式缺货? / 标题 / 信用卡支付 / 活动标签 / 商品规格：… /
平台加补后 / ￥ 现价 [ / 距加入降 / ￥ 降额 ] [ / ￥ 原价 ] / 数量
```

- 有「距加入降」时**第三组**才是原价（第一版把第二组当原价，Lexar 被写成 ¥0.7）。
- 价格组必须以「平台加补后」为锚，最多取 3 组；不设上界会串到相邻条目的价格（曾把数量解析成 369）。
- 数量取所用最后一组价格之后的第一个 1–3 位整数；取第一组之后的整数会把「降额」当数量（曾得 qty=0）。
- 「重新选择规格」「宝贝已不能购买」等字样在**每一行模板里都存在**（CSS 隐藏），因此文本层无法判定真实状态 → 本表不设「状态」列，只在「说明」里登记视觉确认的不可结算条目。
