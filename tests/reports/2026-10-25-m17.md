## 与计划不一致处的处理（已回写 docs/22 §5.1）

1. **E17-2 的「页面自报 `document.title`」改判为「窗口标题变化」**：夹具是 WPF，没有 document.title；窗口标题由控件自己的 Click 回调改写，证明力等价。真实 Chromium 的「点后页面变化」留给 T25 live 冒烟。
2. **click-by-text 归属 `winput click --click-text`**，`wuia` 只提供 `--find-text` 与 `--point`（只读）。点击是注入，必须单独过 input 闸门。
3. **rect-hit 排除容器角色并要求「有名或可点」；auto 不再回落到容器**（否则空白点会报 `under=Window`）。
4. **新增 `ENV_TEXT_OFFSCREEN`**：Chromium 保留滚动出视口的节点（用户 Edge 实测首行 `y=-24512`），按坐标点击会点到窗口外。现在行中心在窗口外即 rc=3 拒绝，提示用 `--text-index` 选可见行。

## 实现要点

- `win/wuia.ps1`：`-FindText`、`-PointMode auto|rect|uia`；`Get-WaRectHit`（暖树、排除 Window/Document/Pane/Group、面积最小同面积更深）、`Get-WaClickableAncestor`、`Test-WaActionable`、`New-WaUnder`、`Get-WaAncestors`；point-with-target 走 find 档树并自动加深（K64）。
- `bin/wuia`：`--find-text/--point-mode`；`--point-mode` 恒传给 payload（首版只在带 `--find-text` 时传，点探测被静默降级成 auto，已修）。
- `bin/winput`：`click --click-text RE [--text-index N]`，必须 `--expect-hwnd`；解析行 → 中心 → `wuia --point` 取 `under` 作 `hit` → 正常点击 → JSON 合并 `hit`。

## 遗留

- `--find-text` 会同时返回容器与内部文本节点（同一段文字两行，例如 Button 与 TextBlock）。这是「诚实的树」而不是去重后的行索引；`--click-text` 用 `--text-index` 选择，默认第 0 行（面积更大、通常是可点容器）。
- live 的「点后页面变化」尚未纳入自动化（T25 只做只读冒烟；真点用户页面需用户同意）。
