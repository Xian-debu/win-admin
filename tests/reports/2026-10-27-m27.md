# M27 / T32 验收报告 — 真实站点冒烟（2026-10-27）

套件：`tests/check-m27.sh`（SKIP 路径 rc=0；夹具彩排 1 passed / 2 skipped / 1 failed，见下）
判据：S20-1..4（docs/24 §3）

## 结论先说

本轮**没有拿到 live 证据**：机器上唯一的 Edge 窗口是**最小化**的 DSH 页面（`win-admin 读取会话并制定升级计划 — DeepSeek Harness …`），没有可见的 B 站创作中心/投稿页，且当前没有 CDP 实例可用。按计划里写死的口径，整套判 SKIP 并以 rc=0 退出：

```
SKIP  S20 live 冒烟：没有可见的 B 站创作中心/投稿页窗口（先把投稿页开到前台再跑）
{"ok":true,"skipped":true,"reason":"NO_BILIBILI_WINDOW","s20":{"passed":0,"skipped":4,"failed":0}}
```

这不是「测过了」，只是「这台机器当前跑不了」。真实站点的机制证据本轮仍由夹具套件承担（m22 7/0、m23 8/0、m24 8/0、m25 10/0）。

## 脚本做到了什么（可执行部分）

| 步骤 | 判据 | 无浏览器时 | 有页面时怎么做 |
| --- | --- | --- | --- |
| S20-1 | 分区选项被滚到可见：`steps>=1` 且 `element.rect ⊆ container.rect` | SKIP | 需人先展开分区面板（打开面板是对真实页面的写操作，不属于 reveal 的职责）；reveal 成功后断言几何包含，再按 Esc 关面板 |
| S20-2 | 标签区加一个标签再复原：`chipsAfter == k+1` 且复原后该 chip 消失 | SKIP | 真实页面命名不可猜，必须给 `S20_2_INPUT`/`S20_2_LIST`；加完按 ctrl+z 并轮询确认 chip 真的没了，没消失就**如实 FAIL**并提示人工清理 |
| S20-3 | 水印开关切两次回到初值 | SKIP | 找 `水印`（可 `S20_3_NAME` 覆盖）→ `wuia --toggle` 两次 → 用 `toggleState` 证明 `S0 != S1 && S0 == S2` |
| S20-4 | 动作前后窗口集合一致 | 与 SKIP 同批（无窗口可比则只在本机跑 SKIP） | `wwin list` 前后差集必须为空 |

另外：缺 input grant 时三个注入步骤一律转 SKIP 而不是跑一半；`S20_HWND` 可以强制指定窗口，但输出会显式打印 `forced window (rehearsal, NOT live evidence)`，避免被当成 live 证据。

## 夹具彩排（证明非 SKIP 分支能跑，不是 live 证据）

用 `chipwin` 夹具强制指定窗口跑同一份脚本：

```
INFO  forced window (rehearsal, NOT live evidence): 5968300
SKIP  S20-1 分区下拉：reveal rc=3 ENV_NO_CONTAINER
FAIL  S20-2 标签区：加了 REHEARSAL-1 但 ctrl+z 未能复原（零副作用失败，需要人工清理）
SKIP  S20-3 水印开关：找不到（/^NOPE$/）
PASS  S20-4 窗口集合与操作前一致（无新窗口/无残留对话框）
1 passed, 2 skipped, 1 failed
```

三条 SKIP/PASS 都是预期语义（夹具里没有可滚容器、没有水印控件、窗口集合不变）；S20-2 的 FAIL 也是预期：WPF ListBox 的 chip 不是文本框，`ctrl+z` 撤不掉——脚本因此**没有**谎报复原成功，而是报出需要人工清理的失败。这条彩排恰好证明了「零副作用」判据是硬的：复原不成立就不许 PASS。

## 怎么跑 live

1. 把 B 站投稿页（`member.bilibili.com/platform/upload/video`）在 Edge 里打开并置于前台（不要最小化）。
2. 手动点开「分区」面板（如果 S20-1 要跑）；需要 S20-2 时展开标签区。
3. `bash tests/check-m27.sh`（可带 `S20_1_NAME=… S20_2_INPUT=… S20_2_LIST=… S20_3_NAME=…`）。
4. 判据：0 failed；SKIP 必须带得出原因（找不到元素 / 缺 grant），不能出现「跑了但没证明」。
