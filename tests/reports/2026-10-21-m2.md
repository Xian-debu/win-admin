## 3. 缺陷复盘（每个都是实测撞出来的）

1. **Out-Plan 被 `| Out-Null` 吞掉**：`winput move 100 100` 返回全 null 字段、winps 打印 `(no output; exit 0)`。原因：dry-run 分支把 JSON 对象管道送进 Out-Null。教训：输出 JSON 的函数不得接管道；PS 里"抑制返回值"和"输出数据"是同一根管道。
2. **`-split '+'` 正则报错**："限定符 {x,y} 前没有任何内容"。组合键解析要用 `-split '\+'`（字面加号）。
3. **事件处理器里捕获不到局部变量**（WPF 测试窗）：Loaded/TextChanged 的 scriptblock 看不到外层 `$h`/`$timer`，必须用 `$script:xxx`。此坑耗了三轮。
4. **WinForms TextBox 没有 UIA 快速模式**（ValuePattern/TextPattern 都没有，只有 MSAA Name），无法作为 C5 回读判据 → 测试窗改用 WPF。
5. **陈旧测试窗实例互相覆盖 JSON**：同标题多实例写同一文件，读到空/旧数据。stop 脚本按 json 里的 pid 精确杀，起窗前先 stop。
6. **wa_require_app 会往 stdout 打印 app 目录**：包装脚本里直接调用会把 JSON 流污染成 `Invalid numeric literal at line 2`；只有 wa_run 内部该调它。

## 4. 结论

M2 全部门槛（C4/C5/C6/C7 + S1/S2/S7）实测通过，输入链路具备四个特性：
确定性目标（每次点击前用 WindowFromPoint 校验根窗口 == --expect-hwnd）、默认不注入（dry-run 优先，--yes 才动）、默认拒绝（无授权/pause 走 exit 4）、结果可独立取证（窗口侧计数器与落盘文本，不只信自己的返回值）。

已知限制：单次调用经 winps 桥约 600–750 ms，批量动作需复合原语（M4）而非循环脚本；IME 输入法候选窗未覆盖，中文一律走剪贴板粘贴（C5 已验）。
