## 3 · 与计划的偏差（实测推翻计划）

1. **E13-2 判据**：原写 focus 后 `state==normal`；夹具窗口最小化前本来就是最大化，focus 后回到最大化。判据改为「回到最小化前的状态」（docs/20 §0.1，SG-0044）。
2. **E15-4 计数口径**：原写 `wuia --find-name . --enabled`；实测 `--find-name .` 漏掉名字为空的 Edit/ComboBox（差 4 个），改用 `--find-type .`（K49，SG-0045）。
3. **E13-3 负例**：无法在验收里稳定构造「动作中途被抢焦点并改状态」，降级为签名一致性正向断言（SG-0046）。
4. **E1 提交前缀**：出现 `bin+ops:` 这类复合对象，规则放宽为「每个部分都必须是已知对象」，否则合法提交被判违规（SG-0048）。

## 4 · 本轮新记的坑（docs/11 K49–K61）

| 编号 | 一句话 |
|---|---|
| K49 | `--find-name .` 漏掉无名控件，数元素用 `--find-type .` |
| K50 | `Image.FromFile` 锁图导致 Save 报 GDI+ 一般错误，改 `ReadAllBytes`+`MemoryStream` |
| K51 | `SW_RESTORE` 会把最大化窗口打回窗口化（v1.1 的隐性副作用） |
| K52 | WPF 子窗 `Owner` 必须在父窗 `Show()` 之后赋值，否则句柄为 0 |
| K53 | DIP ≠ 物理像素（150% 缩放差 1.5 倍） |
| K54 | `grep -c ... || echo 0` 输出两行，整数比较报错 |
| K55 | 一次性写长 bash/PS 脚本易被 `${...}` 插值与引号打断，改分段生成 |
| K56 | `tools.edit` 的 `old_string` 连缩进都要逐字符匹配 |
| K57 | 剪贴板恢复早于 `Ctrl+V` 落地 → 粘出旧内容却报 `ok:true`；改为「轮询焦点值变化后再恢复」 |
| K58 | 夹具 stop 只认自己 pid 文件，套件中断即泄漏，旧窗口抢走新夹具的点击 |
| K59 | 组合键里修饰键抬起太早 → `ctrl+a` 退化成 `a`；修饰键需 ≥60 ms 驻留 |
| K60 | 用 `ctrl+a/ctrl+c` 回读输入框等于往被测输入注入按键，回读要改 UIA |
| K61 | 夹具清扫会误杀同套件已启动的夹具：pid 文件存的是启动器 pid，且 WSL 的 `kill -0` 判不了 Windows pid |

## 5 · 遗留（非遗漏，已文档化）

- `ENV_STATE_CHANGED` 分支无用例（SG-0046）。
- B 站分区二级 hover 菜单仍不进 UIA 树：`hover-menu` 失败即 `ENV_MENU_NOT_SHOWN`，只能选一级项（SG-0041，站点侧限制）。
