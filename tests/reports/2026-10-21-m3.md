## 3. 关键设计与诚实的限制

### 3.1 锁屏/UAC 用“只能更严格”的测试钩子
锁屏会把我自己关在门外（没有密码无法解锁），自动点 UAC 是绝对红线。因此 S3/S4 使用文件钩子 `C:/Users/Public/win-admin/tmp/force-desktop.txt`：

- 钩子**只能声明一个“已锁定/安全桌面”的名字**，永远不会把真实锁屏覆盖成可用；
- 名字匹配 `Winlogon|Secure` → `UAC_SECURE_DESKTOP`，否则 `SESSION_LOCKED`，都是 exit 3；
- 真实检测路径不变（`OpenInputDesktop` + `GetUserObjectInformation`），钩子只是让判据在不解锁的前提下可复现。

### 3.2 签名能证明“没被手改”，不能证明“没被同用户进程伪造”
grant.json 的 `sig = sha256(secret + 规范化字段)`，secret 在 `~/.dsh/win-admin/.grantkey`（600）。这能挡住误编辑、脚本事故、旧版无签名 grant；**挡不住同一 Linux 用户下的恶意进程**（它读得到 key）。真正的进程隔离需要另一个用户/系统服务，那属于 G4 常驻服务授权，本轮不做，已写进 docs/11 限制。

### 3.3 审计是“事后证据”，不是“实时阻断”
`audit/*.jsonl` 追加写，写失败会让动作失败（fail closed），但账本本身不防删除/改写（同一用户可删）。M5 可考虑每日滚动 + 报告里列出总行数；真正防篡改需要外部存储。

### 3.4 全屏像素差有动画噪声
两次截图间隔 1 秒，全屏 diff_pixels=8185（浏览器里的动画角色）。所以 S1 改为**只比较“动作会影响的区域”**（目标按钮矩形），并在该区域得到 0 差异。全屏 0 差异不是可靠判据，这一点写进 docs/11。

## 4. 本轮踩到的坑

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 从 WSL 传 `WA_TESTING=1` 给 payload 完全无效 | WSL 启动 Windows 进程时**不传递** Linux 环境变量（实测 `winps -f` 读到空） | 放弃环境变量通道，改用 Windows 可见路径下的文件钩子（且只允许更严格） |
| 2 | 审计行数对不上 | `bin/winput` 原本在 guard 拒绝时直接 exit，绕过记账 | 所有 exit 路径先设置 `WA_AUDIT_RESULT`，由 EXIT trap 统一写 |
| 3 | 失败 JSON 里 version=unknown | `$env:WA_VERSION` 在 `. $Core` 之后才赋值，wa-core 读到的还是空 | 先设 env 再 dot-source（winput/wclip 各修一处） |
| 4 | S1 的 pixdiff 输出为空 | 生成 RECT 的 jq 表达式里反斜杠被吞掉，输出字面量 `(.button.x),...`，python `int()` 失败 | 改成 `[.button.x,...] | join(",")`，不依赖转义 |
| 5 | 屏幕分辨率在两次验收之间从 2560x1600 变成 1920x1080 | 用户环境变化（外接屏加入/主屏切换），非代码问题 | 所有判据改为读 `wdiag.screen`；报告记录该变化 |
