## 实施中做的三处修正（已回写 docs/24 §5.1）

1. **PatternDefs 缺 Scroll**：`win/wuia.ps1` 的 PatternDefs 只有 Value/Invoke/SelectionItem/Selection/ExpandCollapse/Toggle/ScrollItem/Text，任何元素都永远 `scrollable:false`——第一次手工验证全 false 就是这个原因，不是 ScrollPattern 不存在。补第 69 行 `@{ name = 'Scroll'; p = [System.Windows.Automation.ScrollPattern]::Pattern }` 后 opt-28 立刻 `via:scroll-pattern`。教训：`patterns:[]` 先怀疑自己的探测表，再怀疑目标。
2. **F19-4 的夹具从 Border 换成 GroupBox**：WPF 的 Border/Canvas **没有 automation peer**，control view 和 raw view 都看不到它们，所以「最近的裁剪祖先」在 UIA 里根本不存在，几何兜底也没有比较对象，只能诚实地报 `via:none`。夹具改用 GroupBox（有 peer，ControlType.Group，`ClipToBounds=true`、高 40px、内容 Canvas 把 TextBlock 推到 60px 处）后，`CLIPPED-TEXT` 的 rect 越出 GroupBox 的 rect，`Get-WaClipAncestor` 走几何判定得到 `via:rect`，这正是 F19-4 想表达的「无 ScrollPattern 但确实被裁剪」。真实 WPF 页面里这类祖先通常也是 GroupBox/Panel 而非 Border。
3. **F19-3 的语义收窄为「点必须在目标窗口内」**：`AutomationElement.FromPoint` 是全局的，`--point 5,5` 会返回 NVIDIA 覆盖层（`CEF-OSC-WIDGET`）或 `#32769` 桌面 Pane 的元素——对一个指定了 `--hwnd` 的查询来说那不是「命中」，而是「这个点不在你的窗口里」。现在 `--scroll-info` 先取目标窗口 rect，点在外（±2px）直接 rc=3 `ENV_NO_HIT`（JSON 带 `point` 与 `window`）；`Get-WaOwnerHwnd` 仍保留为二次防线（跨进程元素一律丢弃）。Edge 全屏时不存在真正的「空白点」，所以这条判据必须靠窗口边界，而不是靠屏幕空白。

## 实现要点

- `Get-WaScrollInfo($el,$maxDepth)` 沿 control view 逐级找**自身或祖先中第一个有 ScrollPattern 的节点**，链上每层都记 `scrollable`/`scroll`；找不到 pattern 再找 `clip`（自身 rect 越出祖先 rect ±2 且祖先非 Window），最后兜底 `Get-WaClipAncestor`。
- 点探测先 `FromPoint`，若只拿到容器（Chromium 常见）或拿到别的进程的元素，则回退 `Get-WaElementAtPoint`（暖树里含该点、面积最小、最深者），再算一次。
- 输出：`{ok,mode:"scrollinfo",hwnd,point,element,via,scrollable,container{name,type,aid,class,rect,depth,patterns,scroll},chain,scanned,passes,warmMs,warmRetries,depthUsed}`；find 无 point 时 `point:null`。
- `container.scroll` 只在 `via:scroll-pattern` 时非 null；`percentX/percentY` 为 UIA 的 -1（未知）时输出 `null`，不伪造 0。
- 与 T21 兼容：`--scroll-info` 与 `--point` 的旧输出互不影响（scrollinfo 块插在 point 块之前并 `exit 0`，point 块保持原语义）。
