# win-admin v1.3.0 验收总报告（2026-10-25）

结论：**v1.3.0 冻结**。T20–T26 全部落地；新判据 E16–E18 / C17–C19 全绿；全表回归 242 条断言通过（0 失败，18 SKIP），`check-release.sh` pass=yes。

## 1 · 本版要解决什么

依据 `session-c022d2c2`（v1.2.0 的第一次实战：B 站投稿草稿）逐条取证（`docs/21` 7 条反馈），按 `docs/22` 的冻结判据实施 T20–T26：

| 实战里的卡点 | 本版交出什么 | 套件 |
|---|---|---|
| 「找不到页面元素」，以为工具读不到网页 | 冷暖树预热 + 默认 depth 20 + 落空自动加深到 28 + `passes/warmMs/warmRetries/deepened` 诊断 | m16 |
| 只会按坐标点，点空也不知道点到哪 | 每次 click 带 `hit{name,type,rect,actionable…}`（注入**之前**取），未命中 `hit:null`+`hitReason` | m18 |
| 点完无法证明有后果 | `click --expect-change title|rect [--timeout MS]`：超时 `ENV_NO_EFFECT` + before/after/elapsedMs | m18 |
| 想「点那个写着 XX 的地方」只能先截图量坐标 | `wuia --find-text RE` 文本行 + `winput click --click-text RE` | m17 |
| 网页正文要复制/读屏两套 | `ops/read-text`：UIA TextPattern 优先、剪贴板兜底并还原；真实 Edge 一次 156–173 KB | m20 |
| 输入打到按钮上仍报成功 | `type` 焦点门 `ENV_NO_FOCUS` + 落地断言 `ENV_NO_EFFECT` + `--force` 逃生口 | m19 |
| WSL 路径截图要手抄 | `wshot --out` 直接收 WSL 路径（`/tmp/x.png`），JSON 回 `path`/`wsl_path`/`mapped` | m20 |

## 4 · 回归中发现并修掉的问题

1. **`check-release.sh` 的 UTF-8 窗口再次不够**：`win/wuia.ps1` 的 param 块长到第 42 行，`OutputEncoding` 落到第 43 行，`head -40` 误报 `FAIL no OutputEncoding: wuia.ps1`（m5 因此红）。窗口 40→60 行并同步注释。
2. **`under` 契约被 T22 破坏**（真回归）：T22 把 hover/wheel 的 `under` 换成暖树几何节点、旧答案塞进 `underUia`，m7 的 W2/W3/W6 三条立刻红——`under.window.title` / `under.element.name` 是 v1.1 起写进 SKILL 的契约。改为 `under` 原样保留、暖树命中新增 `underNode`；m18 N4 改断言 `underNode` 且额外断言 `under{window,element}` 仍在。
3. **`--find-class` 是正则**（K71）：T23 给 uiawnd 加了 `wa-ro`（WPF `RichTextBox`），`--find-class TextBox` 子串命中它，m10 F4 从 1 变 2。按设计不改实现，m10 改用 `^TextBox$` 并把坑记进 docs/11。
4. **T23 焦点门改了旧断言的达标路径**：m14 N4 原意是「verify 回读发现没落地」，按钮焦点会让它在更早的 `ENV_NO_FOCUS` 中止 → 加 `--force` 抵达 verify 分支；N10 测 `--text-file` 的 Windows 路径解析、与焦点无关 → 先 `wuia --find-aid wa-edit --focus` 再输入。两条都记进 docs/22 §5.1（18–20 条）。
5. **`--warm-ms/--warm-passes` 只在 SKILL 里、不在 `--help`**：C18-4 的字面判据是「帮助里写的都实现」，反向（文档写了帮助没写）同样会误导人，T26 补齐 help。

## 5 · 判据修正汇总

T20–T26 期间对冻结判据的 20 条修正全部记录在 `docs/22-v1.3-plan.md` §5.1（含理由）。其中影响面最大的三条：

- `--no-warm` 的断言从 `passes==1` 改为 `warmRetries==0`（加深本身也算一次遍历）。
- `hit` 报「可点祖先」而不是落点叶节点（叶节点常是 `TextBlock`、`actionable:false`），原件留 `hit.raw`。
- hover/wheel 保留 `under` 契约、新增 `underNode`（见 §4.2）。

## 6 · 环境与遗留

- 环境：Windows 11 + WSL2，屏幕 2560×1600（150%），SessionId=1 有真实交互桌面；用户 Edge（`0x90cdc`）作为 live 只读靶子。
- 限制（写进 SKILL §10 与 docs/04 §10）：`--expect-change` 只认 `title`/`rect`；`hit` 是 a11y 语义不是像素；冷进程首查 2–3 s 属正常；视口外的文本行会被 `ENV_TEXT_OFFSCREEN` 拒绝而不是盲点。
- 未做：`--expect-change` 支持 `text`/`pixel`；Chromium 二级 hover 菜单的稳定展开；`ops/read-text` 的分页（>1 MB 正文）。
- 已知问题：`docs/11` K1–K71。
