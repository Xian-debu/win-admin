# 01 · 目的与能力边界

> 文档状态：**冻结**（2026-10-20）。改这里的"目的"要单独提交并说明为什么原目的不成立。

## 1. 用户要的是什么

原话（2026-10-20 会话）：

> "我预计的是用它来实现让你在我允许时彻底接管 PC 操作。"

拆成三个必须同时成立的条件：

1. **彻底**：不是"能跑命令"，而是"能看见屏幕、能点到按钮、能打字、能等到界面变化"。
2. **在我允许时**：授权是**事件**，不是**安装状态**。装了插件 ≠ 得到许可；许可要有起点、有范围、有终点。
3. **接管 PC**：对象是 **Windows 桌面**（用户在 Windows 里操作的那台机器），
   而不是 DSH 所在的 WSL 文件系统。

## 2. 我们要交付的东西

一个**能力包**（不是插件，不是第二套 DSH）：

| 交付物 | 形态 | 面向谁 |
|---|---|---|
| 原语工具 | `bin/` 下的 CLI，从 WSL 调用 Windows，输出紧凑 JSON | agent（我方） |
| 守卫层 | `guard/`：授权令牌、急停、审计 | 用户（安全边界） |
| 技能说明 | DSH skill（`SKILL.md`）描述怎么用、什么时候不许用 | agent + 用户 |
| 验收件 | `tests/` 下的可重跑用例 + `docs/07-acceptance.md` | 双方（长期维护） |

## 3. 能力边界（明确不做）

| 不做 | 原因 |
|---|---|
| 自动点 UAC / 提权 | 安全桌面是系统级隔离，任何用户态注入都不该碰；这是**硬边界**，不是实现难度 |
| 免安装的"一键接管" | "在我允许时"要求授权是显式事件；做成一键 = 默认全开 |
| 基于视觉坐标的**唯一**路径 | 视觉模型是否可用未定（见 Q1）；UIA 语义定位是更稳的主路径 |
| 常驻后台的"自主代理" | 无人在场的静默操作是事故来源；本项目所有动作都由一次显式调用触发 |
| 二次发行 / 打包给别人用 | 私人工具，只服务本机；不承担多机兼容 |

## 4. 为什么不用那个网上插件

详见 `docs/03-plugin-review.md`。一句话：它的权限档与 DSH 内置的
`danger-full-access + approval:never` 完全等价（零增益），而它真正带来的 computer use
需要 DSH 跑在 Windows 上；本机 DSH 在 WSL2 内，拿不到 Windows 桌面。
**结论：它解决的问题，我们这儿要么已经解决，要么它解决不了。**

## 5. 验收哲学

三条原则，贯穿 `docs/07-acceptance.md` 的每一条判据：

1. **可复现**：每条验收都给"命令 + 期望值 + 实测值"，不写"应该可以"。
2. **反例优先**：先验收"该拒绝时确实拒绝了"（无授权不点、锁屏不点、UAC 不点），
   再验收"该成功时确实成功了"。安全工具的能力上限由它的失败模式决定。
3. **数字说话**：坐标误差（px）、识别命中率（%）、端到端耗时（ms）、审计完整率（%），
   全部留实测值；达不到就写"未达标"，不写"基本可用"。
