# 24 · v1.4 升级计划（把「能找到」推进到「能滚到位、点得准」）

- 日期：2026-10-27
- 依据：`docs/23-usage-feedback-4.md`（session-dd79939d 取证）、`docs/21`、`docs/22`
- 一句话：真实投稿里唯一卡死人的动作是「在一个比视口长的选项列表里，把指针放进去、hover、滚到目标项、再点」；v1.4 把它变成一条命令，并让「坐标随滚动失效」从习惯问题变成机制问题（每次动作前重新定位 + 命中校验）。

## 2 · 设计与边界（先定不做的事）

1. **滚轮是主路，ScrollPattern 是快路**。用户描述的、也是真实组件响应的路径是「指针进容器 + hover + 滚轮」；`ScrollPattern`（UIA）能省掉输入注入，但 Chromium/自绘控件不一定实现，所以：先试 pattern，`moved:false` 就回落 wheel，两条路都记进 JSON。
2. **每一步都要有正面证据**：滚之前记住容器 `ScrollPercent`，滚之后必须变；不变 → `ENV_SCROLL_NOT_MOVED`（说明指针没在容器里或需要 hover），换 hover 再试一次，仍不变就失败退出，**不许「滚了就算成功」**。
3. **可见性判据是几何**：`element.rect ⊆ container.rect`（±2px）**且** `point` 命中该元素/其后代/可点祖先（复用 T21/T22 的 hit-test）。不做「看起来像在屏幕里」这类模糊判断。
4. **每次动作前重新定位**：reveal / select-option 返回的都是当次查到的 rect 与命中的元素，调用方不需要缓存坐标。
5. **不碰站点实现**：不做 B 站专用选择器；配方写在 docs，机制留在 ops。
6. **默认 dry-run**：`ops/reveal`、`ops/select-option`、`ops/chip-add` 都要 `--yes` 才注入，dry-run 只报计划（会滚几步、点哪里、预期值）。

## 3 · 冻结判据（实施前写死）

### F19 滚动容器与滚动状态（T28）

`bin/wuia --hwnd H --scroll-info --point X,Y`

- **F19-1** 命中可滚动容器（夹具 `wa-scroll` 的列表）：`{"ok":true,"mode":"scrollinfo","scrollable":true,"via":"scroll-pattern"|"rect","container":{"name","type","rect","patterns"},"scroll":{"verticallyScrollable":true,"percentY":N,"viewHeight":N},"point":{...}}`，rc=0。
- **F19-2** 命中不可滚动元素（`SCROLL-TITLE`；夹具里没有 LBL-TITLE，该标签无 aid，按 name 找）：`scrollable:false`、`container:null`、rc=0（不是错误）。
- **F19-3** 点空白：rc=3 `ENV_NO_HIT`（复用 T21 语义）。
- **F19-4** `via` 必须如实：ScrollPattern 可用 → `scroll-pattern` 且 `scroll.percentY` 为数字；不可用 → `rect`，`scroll.percentY` 为 `null`，此时 `container` 仍给最近裁剪祖先的 rect。

### F20 reveal：滚到目标可见（T29）

`ops/reveal --hwnd H (--find-aid|--find-name|--find-text|--find-class) RE [--index N] [--steps 12] [--yes]`

- **F20-1** 目标在容器下方（夹具：容器 240px 高、30 个按钮，目标 `OPT-28`）：`{"ok":true,"revealed":true,"steps":N,"point":{...},"element":{...},"container":{...},"scroll":{"before":x,"after":y},"moved":["pattern"|"wheel",...]}`，rc=0；`element.rect` 完全落在 `container.rect` 内（±2px）；`point` 的 hit-test 命中该元素（或其后代/可点祖先）。
- **F20-2** 幂等：紧接着再跑一次，`steps:0`、`moved:[]`（已在视口内就**不许注入任何事件**）。
- **F20-3** 目标不存在：rc=3 `ENV_NO_MATCH`（复用 wuia 的码），`steps:0`。
- **F20-4** 滚不动：容器已到底/指针不在容器内 → rc=3 `ENV_SCROLL_NOT_MOVED`，带 `scroll.before/after`、`point`、`container`、`hoverTried:true|false`；**不得谎报 revealed**。
- **F20-5** 步数用尽仍不可见 → rc=3 `ENV_NOT_REVEALED`，带 `steps`、`history:[{step,percent,before/after}] `（证明真的试过）。
- **F20-6** dry-run：rc=0、`dryRun:true`、`plannedSteps`≥0、无 `revealed` 字段、不注入。

### F21 选择类控件（T30）

`ops/select-option --hwnd H --trigger RE --option RE [--expect-value RE] [--mode auto|panel|native] [--timeout 4000] [--yes]`

- **F21-1** 面板型（B 站分区那类：点 trigger 在页面内展开列表）：`{"ok":true,"mode":"panel","clicked":{"name","rect"},"value":{"before","after"},"matches":true,"closed":true,"steps":N}`，rc=0。
- **F21-2** 原生弹层型（WPF ComboBox / Chromium `<select>`：弹层是**独立顶层 HWND**，同进程、owner=主窗）：`mode:"native"`，需要 `wuia --hwnd <popup>` 取项；点击允许落在 owner 家族窗口（复用 `--allow-related` 的语义），JSON 回报 `popup.hwnd/title`。
- **F21-3** 选项不存在：rc=3 `ENV_NO_OPTION`，`steps:0`、`tried:["panel","native"]`，并用 Esc 关掉弹层（`closed` 如实回报）。
- **F21-4** 选中后回读不符（`--expect-value`）：rc=3 `ENV_NO_EFFECT`，带 `value.before/after`。
- **F21-5** 视口外选项必须先 reveal 再点：断言 `steps>=1`（夹具里目标在第 28 项）；不允许「直接点 raw rect」通过。

### F22 串行录入（T31）

- **F22-1** `ops/chip-add --hwnd H --input RE --list RE --value TEXT`：`{"ok":true,"chipsBefore":k,"chipsAfter":k+1,"added":TEXT,"retried":0|1}`；每个 chip 文本不得包含「上一个 chip + 本值」的粘连（断言 chip 名 == value，且不存在同时含两个词的 chip）。
- **F22-2** 输入被吞（模拟：首次 Enter 不生效）→ 自动重试一次 → `retried:1` 且 `chipsAfter == k+1`；两次都失败 → rc=3 `ENV_CHIP_MISMATCH` 带 `chips:[...]`。
- **F22-3** `ops/rich-write --hwnd H --point X,Y --text-file F`：点进编辑区 → `ctrl+a` → 粘贴 → 用 `ops/read-text` 回读，`matched:true`（前缀比较，允许编辑器追加换行/占位符）；回读不符 rc=3 `ENV_TEXT_NOT_ENTERED`。
- **F22-4** `ops/wait-ready --hwnd H --require RE --timeout 8000`：`{"ok":true,"polls":N,"elapsedMs":M,"matched":{"name","rect"}}`；超时 rc=3 `ENV_TIMEOUT` 带 `polls`。

### S20 真实站点冒烟（T32）

用户真实 Edge（无调试端口），B 站投稿页，**零副作用**：

- **S20-1** 分区下拉：`ops/reveal` 把「科技数码」滚到可见 → `steps>=1`、`element.rect ⊆ container.rect`；随后 Esc 关闭面板，不改变表单值。
- **S20-2** 标签区：`ops/chip-add` 加一个测试标签 → 复核 chip 数 +1；随后点该 chip 的删除按钮复原（或 `ctrl+z`），核对 chip 数回到原值。
- **S20-3** 水印开关：`ops/reveal` 到「更多设置」里的水印复选框 → 读取当前状态 → 切换一次 → 确认状态变了 → 再切换回来（两次后必须回到初值）。

- 无 Edge / 非投稿页时整份 SKIP（exit 0），与 m21 的 live 口径一致。

## 5 · 实施中允许的判据修正（必须回写本文件）

只允许「证明不了」换成「等价可证」这一类修正，并且必须写清原因；不允许为了让测试变绿而放松「不许谎报成功」的底线。已发生的修正记录在 §5.1。

### 5.1 已发生的判据修正

1. **F19-2 的取样元素**：原文写 `LBL-TITLE`，夹具里实际叫 `SCROLL-TITLE`（无 aid，按 name 找）。判据不变：`scrollable:false`、`container:null`、rc=0。
2. **F19-4 的裁剪祖先必须是「有 automation peer 的容器」**：WPF 的 Border/Canvas 没有 peer，UIA 看不见，「最近的裁剪祖先」无从取得；夹具该用例改用 GroupBox（有 peer）。判据不变（`via:rect`、`percentY:null`、container 给裁剪祖先 rect），但实现上承认：无 peer 的裁剪在 UIA 里不可见，此时如实报 `none`。
3. **F19-3 的「空白点」语义收窄为「点不在目标窗口内」**：`AutomationElement.FromPoint` 全局生效，Edge 最大化时屏幕没有真正的空白点，`5,5` 会命中别的应用的覆盖层。现在点落在目标窗口 rect 外（±2px）即 rc=3 `ENV_NO_HIT`，并带 `point` 与 `window`；跨进程元素另由 `Get-WaOwnerHwnd` 兜底丢弃。语义等价（仍然「点底下没有本窗口的可滚动元素」），且可稳定复现。
4. **F19-1 的 `percentY` 允许为 `0` 但必须是数字**：`opt-28` 在视口外时 ScrollPattern 的 `VerticalScrollPercent` 仍上报 0（WPF 的 Invalidate 时机），所以判据只要求「数字或在 -1 时为 null」，不要求非零；真正的滚动位移由 T29 的 `scroll.before/after` 证明。


## 6 · 风险

1. **虚拟列表**：B 站分区面板可能是虚拟滚动（只有可见项在 DOM/UIA 里）。对策：reveal 每步都重新查树，找不到目标时先滚一屏再查；连续两屏都找不到才判 `ENV_NO_MATCH`（记入 F20-3 的实现细节）。
2. **滚动惯性**：滚轮有惯性/动画，滚完立刻查树会拿到旧 rect。对策：每步 `sleep 80–150ms` 再查；同一位置连续两次 rect 相同才算稳定。
3. **hover 抢焦点**：hover 会不会把焦点从输入框移走（Quill 场景）。对策：reveal 只移动指针不点击；写入类操作（rich-write）自己重新点焦点。
4. **真实站点零副作用**：S20 必须可复原；一旦发现无法复原的动作（如「保存草稿」）就不做，改成只读断言。
