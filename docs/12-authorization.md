# 12 · 夜间自主授权与自授权清单（Self-Grant Ledger）

> 本文件记录 2026-10-21 夜间用户的一揽子授权，以及我自己给自己签发权限时的**强制记账协议**。
> 协议的目的不是形式主义：用户第二天只能靠这份清单判断"昨晚这个 agent 到底自己决定了什么"。

## 1. 用户授权原话（m00805，2026-10-21 00:5x）

```
我接下来要睡觉了，就不盯着你了，你可以一直跑，你遇到的，有自己想法的，我全部授权给你了，
你只需在git提交时单独增量提交一个自授权清单即可，明早我一并查看，我期望你可以一步步自己执行到底。

你可以把上面的内容git提交到win-admin的规划中，然后制定一个goal（以防你断了工作流）。
然后你就可以开工了，逐步推进，逐步验证后git提交，便于你长期的开发和维护。
```

解读（我承担的解释责任）：

1. **范围**：win-admin 项目内，M3 → M4 → M5 的推进，以及推进过程中"有自己想法"的技术决策。
2. **形式**：不需要逐项等待确认；但凡是我**替用户做的决定**，必须单独一次提交写进 `authorization/self-grants.md`。
3. **不变的部分**：`~/.dsh/AGENTS.md` 的红线与三条不可逾越线仍然有效——它们不是"默认值"，是"无论谁授权都不做"。
4. **用户明早的查看成本**：一份清单 + 每个里程碑一份报告，不应要求用户读代码才能判断风险。

## 2. 自授权清单协议（强制）

- 载体：`authorization/self-grants.md`，表格式，只追加（append-only），一行一个自授权。
- 提交方式：**单独一次提交**，前缀 `auth:`，不与代码/文档改动混在同一次提交里（用户可 `git log --grep=^auth:` 一次看全）。
- 触发条件（任一即须记账）：
  1. 我扩大了实现范围或改了已冻结的验收判据；
  2. 我引入了新依赖、新文件类型、新脚本入口；
  3. 我动了系统或用户环境（安装、注册表、计划任务、开机自启、网络、代理）；
  4. 我用"测试钩子/模拟"替代了真实场景来证明某个判据（例如无法真锁屏时的 S3）；
  5. 我决定"不做"某件计划内的事，并给出理由；
  6. 我发现了计划外的风险，并自行选择了缓解方式。
- 每条必填：ID / 时间 / 类别 / 决定 / 依据 / 影响面 / 回滚方式 / 对应提交。
- 类别代号：`SCOPE`（范围）、`TOOL`（依赖/工具）、`SYS`（系统环境）、`GUARD`（安全策略）、`TEST`（测试替代）、`DROP`（决定不做）。

## 3. 即使有全权授权也**不做**的事（红线，非默认值）

| 不做 | 原因 |
|---|---|
| 锁屏（Win+L / LockWorkStation） | 我无法解锁，会把用户锁在门外；S3 改用受控钩子验证（见 SG-0002） |
| 点击 / 回车 UAC 提权对话框 | 提权后的后果不可预演；这是 D9 |
| 读取、复制、外传任何凭据（浏览器密码库、SSH 私钥、token、cookie） | 与本项目无关，且不可撤回 |
| 删除或覆盖用户的个人文件 | 只写 `C:\Users\Public\win-admin\` 与仓库内 |
| 改系统代理 / DNS / 防火墙 / 计划任务 / 开机自启 | 会污染用户环境且难以自证清白 |
| 安装内核驱动、常驻服务 | 违反 D3（无状态载荷）；急停走软通道 |
| 把本机数据上传到外部网络 | 除非是 git push 用户明确要求过的仓库 |
| 在用户自己的窗口里打字 / 点击 | D18：只用自建测试窗或我自己启动的进程 |

## 4. 本次夜间作业的边界（写给自己看）

- 工作目录：`/root/win-admin`；Windows 侧只写 `C:\Users\Public\win-admin\`。
- 桌面可用性：用户睡着后屏幕可能锁/熄。**锁屏时一切 GUI 验收自动 SKIP 并记录**，绝不"想办法绕过去"；屏幕熄但会话未锁时，GUI 动作可能无效——用截图亮度做前置判断，暗屏则 SKIP。
- 时间预算：先 M3（守卫，纯逻辑为主，不依赖人眼），再 M4（复合操作，需要桌面），最后 M5（冻结与发布）。
- 交付：`tests/reports/` 下每个里程碑一份报告；`authorization/self-grants.md` 一份清单；次日晨报给出"做了什么 / 自己决定了什么 / 哪里没验成"。
