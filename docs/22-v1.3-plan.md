## 0 · 一句话

v1.2 让「命令有了且多数可信」；v1.3 解决的是实战里最贵的失败——**动作成功了却不知道有没有作用于目标**。三条主线：

1. **看得见**（T20/T21）：网页 a11y 树冷启动要预热、默认深度要够、文本行要能定位；
2. **点得准**（T21/T22）：click 必须回报命中对象，并能断言「点了之后真的发生了什么」；
3. **错了会喊**（T23/T24）：焦点不在可编辑控件、路径不可写、参数不认识——一律 rc≠0 且给出可行动的 JSON。

## 2 · 设计与边界（先定不做的事）

- **T20 预热只对「拿不到页面内容」的窗口付出代价**：先走一遍树；结果为 0（find）或树里 Document 无页面子节点（tree）→ 休眠 250 ms 重走，最多 3 遍；命中即停。JSON 增 `passes`、`warmMs`、`depthUsed`、`deepened`、`truncated`。`--no-warm` 回到 v1.2 行为（诊断用）。
- **T20 深度**：`--depth` 未显式给出时，find/action 默认 20（tree 仍 3）；空结果自动加深到 28 一次（`deepened:true`）。显式 `--depth` 仍按显式值首查，但同样允许一次自动加深（与 v1.2 的 click-element/wait-uia 对齐）；`--no-deepen` 关闭。
- **T21 文本行索引**来自**暖树**里 `name` 非空、`rect.w>0` 的节点（Text/Button/Hyperlink/ListItem…），按 (y,x) 排序；`--find-text RE` 输出行 + rect + 该行最近的祖先可点元素（若有）。`--click-text RE` = 找到行 → 点行中心 → 回报命中。**不新增 OCR、不接 CDP。**
- **T21 几何 hit-test**：`--point X,Y` 先 FromPoint；若返回 null 或只有 Document/Pane（Chromium 特征）→ 用暖树里**包含该点的最小 rect** 节点（同尺寸取更深/更小者），JSON `via:"rect-hit"`。这是 T22 命中回报的地基。
- **T22 click 命中回报**格式统一为 `hit:{type,name,aid,class,rect,via,actionable}`；`actionable` 由类型+模式判定（Button/Hyperlink/ListItem/CheckBox/ComboBox/Edit + 有 Invoke/Toggle/SelectionItem/Value 之一）。
- **T22 效果断言**：`--expect-change EVENT --timeout MS`。EVENT ∈ `title`|`url`|`window`|`dialog`|`text:RE`|`name:RE`|`value:RE`。判定用「点击前快照 vs 点击后轮询」；超时 → `ENV_NO_EFFECT` rc=3，JSON 带 `expect`、`before`、`after`、`hit`、`elapsedMs`、`attempts`，并把「期间是否出现新顶层窗口/对话框」写成 `observed.dialog` 供 F7 判读。
- **T22 无效果 ≠ 无命中**：`hit` 只说明落点是谁；`--expect-change` 才说明有没有后果。两者分开，避免又把「点到了但按钮没功能」说成「没点到」。
- **T23**：type 在粘贴前查焦点（`--allow-empty-focus` 可关）；粘贴后若「可回读且值没变」→ rc=3 `ENV_NO_EFFECT`；两者都可 `--force` 越过（记 `forced:true`）。**m9 的 L5/L6 必须仍绿**。
- **T24**：`wshot --out` 若拿到非 Windows 路径（如 `/tmp/x.png`）→ 写 `C:/Users/Public/win-admin/tmp/shot-<sha1前8>.png` 再 `cp` 回目标，JSON 同时给 `path`（Windows 落点）与 `wsl_path`（用户给的路径）；`ops/read-text` = `--hwnd|--title` + TextPattern → 剪贴板兜底，输出 `{text,chars,source,ms}`；`wwin focus --yes` 兼容接受并在 JSON 标 `ignoredFlags:["--yes"]`。
- **T25 live 冒烟**只做**只读**：打开 B 站首页（受管或用户浏览器均可），断言 `find-text 投稿` / `find-type Edit` 有结果、`--point` 命中页面元素；无网络直接 SKIP，不计入失败。

## 3 · 冻结判据（实施前写死）

### E16 树可靠性（T20）
- E16-1 冷进程首查：夹具窗口就绪后**第一次**调 `bin/wuia --hwnd H --find-name '^深层按钮$'`（不传 --depth/--max）→ `total>=1`。
- E16-2 JSON 含 `passes`（1..3）、`warmMs>=0`、`depthUsed`；`--no-warm` 时 `passes==1`。
- E16-3 默认深度：depth 22 的页面元素在不传 `--depth` 时能找到。
- E16-4 自动加深：显式 `--depth 12` 查 depth 22 元素 → 首查 0 后 `deepened:true` 且最终 `total>=1`；加 `--no-deepen` → `total==0` 且 `deepened:false`。
- E16-5 性能：暖树整树（B 站首页 561 节点）单次 `--find-name` ≤ 5 s；冷进程首查（含预热）≤ 9 s。

### E17 文本行与命中（T21）
- E17-1 `--find-text '深层按钮'` 返回 ≥1 行，行含 `text/rect/depth`，`rect.w>0 && rect.h>0`，按 y 升序。
- E17-2 `--click-text '深层按钮'` 点击后夹具页面自报被点元素（`document.title='clicked:deep-btn'`）→ `hit.name` 与 `hit.rect` 含点击点，`ok:true`。
- E17-3 `--point` 在页面文本中心 → `under` 非 null，`via:"rect-hit"`，且 `under.rect` 包含该点；FromPoint 直命时 `via:"uia-point"`。
- E17-4 `--point` 在空白（无节点包含）→ `under:null` + `code:"ENV_NO_HIT"`（rc=3），不再只给 Document 祖先。

### E18 点击闭环（T22）
- E18-1 `winput click X Y --expect-change title --timeout 3000` 命中改标题按钮 → `ok:true`、`changed:true`、`before/after.title` 不同、`hit.actionable:true`。
- E18-2 点页面空白（无效果）同参数 → rc=3 `ENV_NO_EFFECT`，JSON 含 `hit`、`elapsedMs>=timeout-500`、`observed`。
- E18-3 每次 click 都带 `hit` 字段（命中为对象，未命中为 `null` + `hitReason`）。
- E18-4 `ops/click-element` 对无 Invoke 但有 rect 的节点回落坐标点击 → `strategy:"coords"`；点击前 hit-test 与目标不是同一节点 → rc=3 `ENV_HIT_MISMATCH`。
- E18-5 `winput hover X Y` 返回 `under`（暖树几何），不再是「窗口+RootWebArea」。

### C17 焦点契约（T23）
- C17-1 焦点不在可编辑控件时 `type --text 'x'` → rc=3 `ENV_NO_FOCUS`，JSON `target` 不为 null 时不置 ok。
- C17-2 可回读且值未变 → rc=3 `ENV_NO_EFFECT`（`pasteSettled:false`）。
- C17-3 `--force` 保留 v1.2 行为（ok:true + `forced:true`）。
- C17-4 回归：m9 L5/L6、m8 K1–K4、m14 全绿。

### C18 路径与只读（T24）
- C18-1 `wshot --out /tmp/v13.png` → rc=0，`/tmp/v13.png` 存在，`sha256` 与 JSON 一致，`path` 为 Windows 落点，`wsl_path` 为目标路径。
- C18-2 `ops/read-text --hwnd H`（网页）→ `source:"uia"`、`chars>50`；非 Chromium 夹具回落时 `source:"clip"`（用 testwin 验证）。
- C18-3 `wwin focus --yes` rc=0，JSON `ignoredFlags` 含 `--yes`。
- C18-4 SKILL/文档里不再出现未实现参数（用 grep 断言）。

### S12 文档与发布（T26）
- docs/21、docs/22 落地；K62–K66 入 docs/11；docs/18 加更正注记；docs/04 能力矩阵更新；SKILL/CHANGELOG/VERSION=1.3.0。
