# 22 · v1.3 升级计划（把「能点」推进到「知道点到了什么」）

> 依据：`docs/21-usage-feedback-3.md`（session-c022 实战 7 条 → 5 个工具缺口 + 1 个默认参数缺陷 + 1 处文档漂移）。
> 前置：v1.2.0 已冻结（`927ab5e` / tag `v1.2.0`），全表回归 187 断言全绿。
> 冻结方式：判据先写死（§3），按 T20→T26 顺序实施，**一步一提交、每步自带验收**；判据未冻结前不动代码。
> 红线不变：不碰用户真实 Edge 的启动参数/调试端口，不注入 JS，不读 cookie。

## 0 · 一句话

v1.2 让「命令有了且多数可信」；v1.3 解决的是实战里最贵的失败——**动作成功了却不知道有没有作用于目标**。三条主线：

1. **看得见**（T20/T21）：网页 a11y 树冷启动要预热、默认深度要够、文本行要能定位；
2. **点得准**（T21/T22）：click 必须回报命中对象，并能断言「点了之后真的发生了什么」；
3. **错了会喊**（T23/T24）：焦点不在可编辑控件、路径不可写、参数不认识——一律 rc≠0 且给出可行动的 JSON。

## 2 · 设计与边界（先定不做的事）

- **T20 预热只对「拿不到页面内容」的窗口付出代价**：先走一遍树；结果为 0（find）或树里 Document 无页面子节点（tree）→ 休眠 250 ms 重走，最多 3 遍；命中即停。JSON 增 `passes`、`warmMs`、`depthUsed`、`deepened`、`truncated`。`--no-warm` 回到 v1.2 行为（诊断用）。
- **T20 深度**：`--depth` 未显式给出时，find/action 默认 20（tree 仍 3）；空结果自动加深到 28 一次（`deepened:true`）。显式 `--depth` 仍按显式值首查，但同样允许一次自动加深（与 v1.2 的 click-element/wait-uia 对齐）；`--no-deepen` 关闭。
- **T21 文本行索引**来自**暖树**里 `name` 非空、`rect.w>0` 的节点（Text/Button/Hyperlink/ListItem…），按 (y,x) 排序；`--find-text RE` 输出行 + rect + 该行最近的祖先可点元素（若有）。`--click-text RE` = 找到行 → 点行中心 → 回报命中。**不新增 OCR、不接 CDP。**
- **T21 几何 hit-test**：`--point X,Y` 先 FromPoint；若返回 null 或只有 Document/Pane（Chromium 特征）→ 用暖树里**包含该点的最小 rect** 节点（同尺寸取更深/更小者），JSON `via:"rect-hit"`。这是 T22 命中回报的地基。
- **T22 click 命中回报**格式统一为 `hit:{type,name,aid,class,rect,via,actionable}`；`actionable` 由类型+模式判定（Button/Hyperlink/ListItem/CheckBox/ComboBox/Edit + 有 Invoke/Toggle/SelectionItem/Value 之一）。
- **T22 效果断言**：`--expect-change EVENT --timeout MS`。EVENT ∈ `title`|`url`|`window`|`dialog`|`text:RE`|`name:RE`|`value:RE`。判定用「点击前快照 vs 点击后轮询」；超时 → `ENV_NO_EFFECT` rc=3，JSON 带 `expect`、`before`、`after`、`hit`、`elapsedMs`、`attempts`，并把「期间是否出现新顶层窗口/对话框」写成 `observed.dialog` 供 F7 判读。
- **T22 无效果 ≠ 无命中**：`hit` 只说明落点是谁；`--expect-change` 才说明有没有后果。两者分开，避免又把「点到了但按钮没功能」说成「没点到」。
- **T23**：type 在粘贴前查焦点（`--force` 可越过）；粘贴后若「可回读且值没变」→ rc=3 `ENV_NO_EFFECT`；两者都可 `--force` 越过（记 `forced:true`）。**m9 的 L5/L6 必须仍绿**。
- **T24**：`wshot --out` 若拿到非 Windows 路径（如 `/tmp/x.png`）→ 写 `C:/Users/Public/win-admin/tmp/shot-<sha1前8>.png` 再 `cp` 回目标，JSON 同时给 `path`（Windows 落点）与 `wsl_path`（用户给的路径）；`ops/read-text` = `--hwnd|--title` + TextPattern → 剪贴板兜底，输出 `{text,chars,source,ms}`；`wwin focus --yes` 兼容接受并在 JSON 标 `ignoredFlags:["--yes"]`。
- **T25 live 冒烟**只做**只读**：打开 B 站首页（受管或用户浏览器均可），断言 `find-text 投稿` / `find-type Edit` 有结果、`--point` 命中页面元素；无网络直接 SKIP，不计入失败。

## 3 · 冻结判据（实施前写死）

### E16 树可靠性（T20）
- E16-1 冷进程首查：夹具窗口就绪后**第一次**调 `bin/wuia --hwnd H --find-name '^深层按钮$'`（不传 --depth/--max）→ `total>=1`。
- E16-2 JSON 含 `passes`（1..3；自动加深也算一遍，故**可能为 2**）、`warmMs>=0`、`depthUsed`（tree 同时给 `depth` 与 `depthUsed`）、`warmRetries`；`--no-warm` 时 `warmRetries==0`（口径调整见 §5）。
- E16-3 默认深度：depth 23 的页面元素（夹具实测叶控件在 depth 23）在不传 `--depth` 时能找到。
- E16-4 自动加深：显式 `--depth 12` 查 depth 23 元素 → 首查 0 后 `deepened:true` 且最终 `total>=1`；加 `--no-deepen` → `total==0` 且 `deepened:false`（预热重试仍在，`passes` 可 >1）。
- E16-5 性能：暖树整树（B 站首页 561 节点）单次 `--find-name` ≤ 5 s；冷进程首查（含预热）≤ 9 s。

### E17 文本行与命中（T21）
- E17-1 `--find-text '深层按钮'` 返回 ≥1 行，行含 `text/rect/depth`，`rect.w>0 && rect.h>0`，按 y 升序。
- E17-2 `--click-text '深层按钮'` 点击后夹具页面自报被点元素（`document.title='clicked:deep-btn'`）→ `hit.name` 与 `hit.rect` 含点击点，`ok:true`。
- E17-3 `--point` 在页面文本中心 → `under` 非 null，`via:"rect-hit"`，且 `under.rect` 包含该点；FromPoint 直命时 `via:"uia-point"`。
- E17-4 `--point` 在空白（无节点包含）→ `under:null` + `code:"ENV_NO_HIT"`（rc=3），不再只给 Document 祖先。

### E18 点击闭环（T22）
- E18-1 `winput click X Y --expect-change title --timeout 3000` 命中改标题按钮 → `ok:true`、`changed:true`、`before/after.title` 不同、`hit.actionable:true`。
- E18-2 点页面空白（无效果）同参数 → rc=3 `ENV_NO_EFFECT`，JSON 含 `hit`、`elapsedMs>=timeout-500`、`observed`。
- E18-3 每次 click 都带 `hit` 字段（命中为对象，未命中为 `null` + `hitReason`）。
- E18-4 `ops/click-element` 对无 Invoke 但有 rect 的节点回落坐标点击 → `strategy:"coords"`；点击前 hit-test 与目标不是同一节点 → rc=3 `ENV_HIT_MISMATCH`。
- E18-5 `winput hover X Y` 返回 `under`（暖树几何），不再是「窗口+RootWebArea」。

### C17 焦点契约（T23）
- C17-1 焦点不在可编辑控件时 `type --text 'x'` → rc=3 `ENV_NO_FOCUS`，JSON `target` 不为 null 时不置 ok。
- C17-2 可回读且值未变 → rc=3 `ENV_NO_EFFECT`（`pasteSettled:false`）。
- C17-3 `--force` 保留 v1.2 行为（ok:true + `forced:true`）。
- C17-4 回归：m9 L5/L6、m8 K1–K4、m14 全绿。

### C18 路径与只读（T24）
- C18-1 `wshot --out /tmp/v13.png` → rc=0，`/tmp/v13.png` 存在，`sha256` 与 JSON 一致，`path` 为 Windows 落点，`wsl_path` 为目标路径。
- C18-2 `ops/read-text --hwnd H`（网页）→ `source:"uia"`、`chars>50`；非 Chromium 夹具回落时 `source:"clip"`（用 testwin 验证）。
- C18-3 `wwin focus --yes` rc=0，JSON `ignoredFlags` 含 `--yes`。
- C18-4 SKILL/文档里不再出现未实现参数（用 grep 断言）。

### S12 文档与发布（T26）
- docs/21、docs/22 落地；K62–K66 入 docs/11；docs/18 加更正注记；docs/04 能力矩阵更新；SKILL/CHANGELOG/VERSION=1.3.0。
- `tests/check-m16..m18` 全绿 + 全表回归（m1–m15 原数字不退化）+ `check-release.sh` pass=yes。
- tag `v1.3.0`、推 GitHub；gen24-admin docs/38 §6 回填。

## 5 · 实施中允许的判据修正（必须回写本文件）

与 v1.2 同样口径：实测推翻判据时，先改判据与理由，再改测试，最后代码——三者同一次提交里可见。

### 5.1 已发生的判据修正（v1.3）

1. **E16-2「`--no-warm` → passes==1」改为「`--no-warm` → warmRetries==0」**（2026-10-25，T20）。
   理由：`passes` 计的是遍历次数，**自动加深也会多走一遍**，与预热重试是两条独立路径。实测 deepwin 夹具 `--no-warm --find-aid deep-btn` → `passes=2, warmRetries=0, deepened=true`（首查 20 层未命中 → 加深到 28 → 命中）。要断言「预热没发生」只能看 `warmRetries`；同时新增该字段。
2. **E16-3/E16-4 的元素深度 22 → 23**（2026-10-25，T20）。
   理由：deepwin 夹具是 22 层 GroupBox 包叶控件，实测叶 Button `deep-btn` 的 UIA depth = 23（根 Document 记 depth 0）。原文 22 是设计估算，以实测为准。
3. **tree 输出补 `depthUsed`**（2026-10-25，T20）。
   理由：§3 要求「JSON 增 passes/warmMs/depthUsed/deepened/truncated」，tree 分支只有 `depth`（v1.0 字段名）。补 `depthUsed` 与 `depth` 同值并列，老调用方与判据都能读。
4. **E17-2 的「页面自报 `document.title`」改为「夹具窗口标题 `clicked:deep-btn`」**（2026-10-25，T21）。
   理由：自动化夹具是 WPF（无 `document.title`），而判据真正要证明的是「点到的确实是那一行文本所在的控件」。窗口标题变化同样由控件自己的点击回调触发，是等效证据；真实 Chromium 上的「点后页面变化」由 T25 live 冒烟另行覆盖。
5. **click-by-text 落在 `winput click --click-text`，`wuia` 保持只读**（2026-10-25，T21）。
   理由：点击是注入，必须过 `guard/check.sh input`；`wuia` 的动作全部要 grant，而 `--find-text` 只是读树。与 SG-0039「看与点分属两个命令」同口径。
6. **E17-3 的 rect-hit 排除容器角色（Window/Document/Pane/Group），并要求「有名字或可点」；auto 模式不再回落到容器**（2026-10-25，T21）。
   理由：Chromium 的 `FromPoint` 对页面点常返回 Document（docs/21 F1/F3），若不排除，「空白也有命中」。实测 deepwin 窗口右下角空白：改前报 `under=Window`，改后 `rc=3 ENV_NO_HIT`。
7. **新增 `ENV_TEXT_OFFSCREEN`（rc=3）：`--click-text` 选中的行若落在目标窗口矩形外，拒绝点击**（2026-10-25，T21）。
   理由：真实页面里滚动出视口的节点仍留在 a11y 树中且带 rect（实测用户 Edge 上 `find-text '.'` 首行 `y=-24512`）。按坐标点击会点到窗口外（别的程序上），是真实危险；必须显式 `--text-index` 选可见行。
8. **E18-1 的 `hit` 报「可点祖先」而非落点叶节点**（2026-10-25，T22）。
   理由：FromPoint / rect-hit 在按钮中心命中的是按钮内部的 TextBlock（实测 deepwin「深层按钮」中心 → `ControlType.Text`，`actionable:false`），若照实上报，`hit.actionable` 恒为 false、判据失去意义。现 `under` 保留逐字答案并附 `clickable`（最近可点祖先），`winput` 在 `actionable:false` 时把 `hit` 换成 clickable，并把叶节点原件放进 `hit.raw`——既不撒谎也不丢证据。
9. **`ops/click-element` 坐标路径的 hit-test 在注入之前，且命中别的窗口 → rc=3 `ENV_HIT_MISMATCH`，先于 grant 检查**（2026-10-25，T22）。
   理由：把 uiawnd 盖在 deepwin 按钮上实测，坐标会注入到错误窗口；事后 `--expect-change` 只能发现「没效果」，发现不了「点错地方」。环境判据（落点归属）先于权限判据（grant）是有意的：前者不改状态，越早拒绝越安全。
10. **T23 的 m19 独立成套件；焦点门按「模式可写性」判、落地判定仅在可回读时生效**（2026-10-25，T23）。
    理由：(a) docs/22 §4 原写「m19（m9 扩展）」，若把焦点判据塞进 m9，免引号输入（L1–L7）与焦点契约（C17）的失败会混在同一份报告里，无法判断是输入通道坏了还是落点没选好——按 m16–m18 先例独立为 `tests/check-m19.sh`，m9 原样保留作回归。(b) 焦点「能不能收文本」不能只看 `ControlType`：只读 `RichTextBox` 是 `ControlType.Document` 且有 TextPattern，按类型判会误判为可编辑；改用 `ValuePattern.IsReadOnly=false` → `TextPattern` 只读 → 无模式 三级判定，实测 Button 报 `no Value/Text pattern`、只读编辑器报 `text is read-only`。(c) `ENV_NO_EFFECT` 只在「焦点元素值可回读」时成立（`sawReadable`），否则自绘控件会被误判为「没落地」；`--no-restore-clip` 与 `--force` 同样跳过该判定，并在 JSON 里如实标 `clipRestored:false` / `forced:true`，不假装成功。

11. **C18-2 的 clip 分支由新增的 `ops/read-text --force-clip` 验证**（2026-10-25，T24）。
    理由：本机实测 WPF TextBox/RichTextBox、WinForms、conhost 控制台**都带** TextPattern（conhost 一次读到 242 字符），「天然无 TextPattern 且可复制」的窗口只有 Chromium a11y 未就绪的瞬间状态，套件里无法稳定复现，也不该在用户真机上去赌。`--force-clip` 跳过 UIA、只走 ctrl+a/ctrl+c 这条注入通道，验证的是真实回落路径的同一段代码；断言文本一致、`clipRestored:true`、剪贴板回到哨兵值。
12. **`ops/read-text` 的 `hwnd` 原样回显调用者写法**（2026-10-25，T24）。
    理由：`0x90cdc` 与十进制都是合法入参（`op_resolve_hwnd` 两种都收），内部只作定位；`--argjson` 吃不了 `0x` 前缀，改用 `--arg` 后自然保留原样。m20 N5 的断言由「等于 0x 十六进制」放宽为「非空」，N1/N6 仍按各自入参精确比对。
13. **`wwin focus --yes` 的容忍只限 focus 子命令**（2026-10-25，T24）。
    理由：focus 从不注入，所以「确认」没有意义，用户按 set 的习惯多写 `--yes` 时应照做并说明（`ignoredFlags:["--yes"]`）；`list/info/close/state` 不注入也不该被同一宽容松掉参数校验，仍是 rc=2。
14. **C18-4 的「文档不再出现未实现参数」在 T24 阶段落在 `--help` 上**（2026-10-25，T24）。
    理由：T24 只实现原语，SKILL/docs 的 v1.3 叙述是 T26 的事；此处先保证「帮助里写的旗标都真的实现」（m20 N10 grep 四个新旗标），T26 再把 SKILL 与新旗标对齐。
15. **T25 live 冒烟的取样带**（2026-10-25，T25）：N1 用 `--limit 120` 并断言 `total>=20`、几何行 ≥3、`depth>=8` 行 ≥3；N3 只取 `rect.y` 在 150–1450（跳过浏览器工具栏、排除视口外负坐标）且 `depth>=8` 的行探测。
    理由：Chromium 树里滚出视口的内容仍带 rect，但 `y` 是很大的负数（实测首行 -48412），工具栏行 `depth` 只有 7–8；按原判据 `y>0 && depth>=8` 取样，真实页面上必然一行都取不到（m21 首轮 N3 因此 SKIP）——坏的是取样，不是 hit-test。
16. **B 站专属断言只在活动标签确为 B 站时执行，否则 SKIP（不切标签）**（2026-10-25，T25）。
    理由：UIA 只暴露活动标签页；C19 的「只读」包含「不改变用户浏览器状态」，切标签会动到用户正在用的页面。SKIP 不计失败——整个 T25 套件可跳过是既定性质（无浏览器时 exit 0）。
17. **m21 不需要 grant**（2026-10-25，T25）。
    理由：全部调用走 `bin/wuia` 的只读通道（`--find-text/--find-type/--point/--find-name`），不涉及注入；需要 input grant 的只有 `--click-text` 这类注入动作，而 T25 明确不做点击。
