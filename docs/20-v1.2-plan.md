## 1 · 目标（可判定）

1. **不再有看不见的副作用**：任何只读/复合操作跑完，目标窗口的 placement 与执行前一致；不一致必须报错（不是静默）。
2. **输入必须可回读**：`winput type --verify` 能回答「文本真的进去了吗」，且与 `ops/fill` 同一口径。
3. **坐标不再靠换算**：`wshot` 的图与参数一一对应（`--box` 不会误读），并且能一步把「看得见的控件」变成「点得中的坐标」（`ops/map`）。
4. **点击有结果断言**：`click-element --expect-gone/--expect-alive` 让「点了之后界面该变成什么样」写进命令，而不是写在操作者脑子里。

## 2 · 非目标（本轮明确不做）

- 不做 OCR / 模板匹配（寻找图标按钮仍靠 UIA 名或人工）。
- 不做 B 站专属适配层（分区二级菜单不进 UIA 树是站点侧限制；红线仍是不硬点）。
- 不改 v1.0/v1.1 已冻结判据；新判据追加为 E13–E15 / C14–C16 / S10–S11。
- 不引入 Windows 侧第三方包（保持 PowerShell 内置 UIA + Win32 P/Invoke）。
- 不默认开启 `--verify` / `--allow-related`（见 SG-0036/SG-0037：默认行为必须与 v1.1 一致，避免既有脚本静默变形）。

## 3 · 任务分解（T = 一个提交单位）

### T12 · 焦点/状态安全（G1）

问题：`Set-WaForeground` 无条件 `ShowWindow(SW_RESTORE)`，把最大化窗口打回窗口化（F3）。

- `win/lib/wa-core.ps1`：`Set-WaForeground` 先读 `GetWindowPlacement`；**只有 `showCmd==2`（最小化）才 `ShowWindow(SW_RESTORE=9)`**，其余情况不调 `ShowWindow`，直接走 `BringWindowToTop` / `SetForegroundWindow` / `AttachThreadInput` 重试链。
- 同一规则用于 `win/winput.ps1` 的 `-Focus` 分支（抽出 `Restore-IfMinimized` 到 core，两处共用一个实现）。
- `ops/lib-ops.sh`：新增 `op_state_guard_begin/end`——`op_focus` 前记 `wwin state`，动作后重读；若 state 或 rect 变化且动作不是 `wwin set`，返回 `ENV_STATE_CHANGED` rc=3，JSON 带 `stateBefore/stateAfter`。四个 ops（click-element / fill / wait-uia / hover-menu）在成功路径的 JSON 里加 `statePreserved: true`。
- 期望的语义：focus 之后**只有**「前台窗口」变了，placement 不变。

### T13 · 窗口族匹配（G2）

问题：父子对话框与父窗口判为 mismatch（F1）；mismatch 报错不告诉人「挡在前面的是谁」（F8）。

- `winput click --allow-related`（默认关）：把「命中 hwnd」与「目标 hwnd」各自沿 `GetAncestor(GA_PARENT)` 走到根，若两条链有交集（互为祖先/后代）则视为同族，`matched:"related"`；否则仍 `ENV_WINDOW_MISMATCH`。
- `--allow-related` 不放宽「必须给 `--expect-hwnd`」，也不放宽前台检查（前台只要与目标同族即算）。
- mismatch 的 JSON 增 `hit:{hwnd,title,class,pid,rect}`，msg 里带 title，让人一眼看出是「坐标算错」还是「有东西盖住」。
- `ops/click-element` / `ops/hover-menu` / `ops/fill` / `ops/wait-uia` 增 `--allow-related` 透传。

### T14 · 输入闭环（G3）

问题：`--text-file` 的 WSL 路径失效且错误码混用（F4）；`type` 报成功但内容没进去（F5）；原生对话框路径斜杠差异（F2）。

- `bin/winput`：`--text-file` 的值先判断——`/mnt/...` 或相对路径可读则**在 bash 侧读入**，写入 `$APP_ROOT/tmp/type-$$.txt`（Windows 路径）再交给 PS；读不到 → `ARG_TEXT_FILE_NOT_FOUND` rc=2（msg 带 path）；读到空 → `ARG_EMPTY_TEXT` rc=2。这样 WSL 路径、Windows 路径、相对路径三种写法都成立。
- `winput type --verify [--verify-mode exact|contains]`（默认 `contains`）：动作后取 UIA 焦点元素，读 `ValuePattern`（`<input>`/`TextBox`）或 `TextPattern`；`contains` 判包含、`exact` 判全等；不符 → `ENV_TEXT_NOT_ENTERED` rc=3；焦点元素没有可读 value/text → `ENV_TEXT_UNVERIFIABLE` rc=3。JSON 增 `verify:{focused,hwnd,value,matched,mode}`。
- 新增 `bin/wclip set --native-path`（或 `--path-style backslash`）：把 `C:/x/y` 规范成 `C:\x\y` 再写剪贴板——原生对话框路径问题从此不用记。
- `ops/fill` 的 readback 与 `type --verify` 共用一套判据实现（`--verify-mode` 语义一致）。

### T15 · wshot 坐标契约（G4）

问题：`--rect` 只认 `X,Y,W,H`，按 `X1,Y1,X2,Y2` 写会越界且失败信息不指导（F7）；图与物理像素的对应关系没有字段说明（F6）。

- 新增 `--box X1,Y1,X2,Y2`（左上右下），内部换算为 `X,Y,W,H`；`--box` 与 `--rect` 互斥。
- `--clip`：越界时裁剪到屏幕内，JSON 带 `clipped:true` 与最终 rect；不加 `--clip` 时越界仍 `ARG_OUT_OF_SCREEN` rc=2，但 msg 必须给出：请求的 rect、屏幕 rect、换算后的 W/H、以及两条改正建议（`--clip` / `--box`）。
- 参数形态错误（如 `--rect` 给 4 个空格分隔值）→ `ARG_BAD_RECT` rc=2，msg 写明 `--rect X,Y,W,H（单值）` 与 `--box X1,Y1,X2,Y2` 两种写法。
- JSON 增 `scale`（`dpi/96`，实测 1.5）、`image:{w,h}`、`rect:{x,y,w,h}`；`--grid` 的 help 与 SKILL 写明「图是物理像素，看图点坐标必须开 grid 或按 scale 换算」。

### T16 · `ops/map` 元素地图（G5，新能力）

问题：实战主路径是「截图 → 看图 → 猜坐标」（68 次 wshot + 41 次 click），因为页面控件名不可用。

`ops/map --hwnd H [--out PATH.png] [--depth 16] [--max 400] [--text] [--min-w N] [--min-h N]`

- 枚举 UIA 树中 `IsOffscreen=false` 且 `rect.w>0 && rect.h>0` 的节点，按 (y,x) 阅读顺序编号；输出 JSON `{ok,nodes:[{idx,role,name,aid,rect:{x,y,w,h},patterns,actionable}],count,png}`。
- `png`：在截图上给**可操作**节点画 2px 红框并在框左上角标 `idx`（黄底黑字，8pt），非可操作节点只画淡框（灰）——这样图上看到的就是「能点的东西」。
- `--text`：只出清单不出图（零截图开销，用于「这页有哪些按钮」这类问题）。
- 编号稳定：同一棵树两次调用 idx 一致（排序键 `(y,x,role,name)`）。
- `ops/map` 是只读操作：需要 `scope=shot,uia`，**不需要 input**。`--click IDX` 本轮不做（点击仍走 `ops/click-element --find-name`，避免把「看」和「点」混在一个命令里）。

### T17 · 点击结果断言（G6）

问题：chip 漂移误删、点击成功与否全靠再看一张图（F5）。

- `ops/click-element --expect-gone NAME [--expect-timeout MS]`：点击后轮询，目标节点消失 → `{expect:{gone:true,waited_ms}}`；超时仍在 → `ENV_EXPECT_FAILED` rc=3。
- `--expect-alive NAME`：反向（点击后目标应出现/仍在），超时不存在 → `ENV_EXPECT_FAILED` rc=3。
- 两个断言都在**点击之后**；dry-run 分支只打印将要断言什么。
- SKILL 增「标签 chip 增删配方」：每删一个 chip 都要重新 `wuia --find-name '×'`/`find-aid` 定位，不许复用上一次坐标；点击带 `--expect-gone <chip 名>`。

## 4 · 冻结判据（验收）

### E13 · 状态无副作用（T12）
- E13-1 最大化窗口上执行 `wwin focus --hwnd H` → 之后 `wwin state` 仍 `maximized:true`、`showCmd==3`、rect 与执行前逐值相同。
- E13-2 最小化窗口上 `wwin focus` → 之后 `state==normal` 且前台是该窗口（允许从最小化恢复）。
- E13-3 `ops/hover-menu`（成功与失败两种分支）、`ops/click-element`、`ops/fill`、`ops/wait-uia` 跑完，目标窗口 placement 前后一致，成功 JSON 含 `statePreserved:true`；构造一个「被别的进程抢焦点并改变状态」的场景时返回 `ENV_STATE_CHANGED` rc=3（用夹具模拟：动作中途 `wwin set --state min` 不应出现，故该负例以直接调用 `op_state_guard` 的方式覆盖）。

### E14 · 输入可回读（T14）
- E14-1 `--text-file /tmp/x.txt`（WSL 路径，内容含中文与引号）→ 文本进入目标框，`--verify` 通过，JSON `verify.matched==true`。
- E14-2 不存在的路径 → `ARG_TEXT_FILE_NOT_FOUND` rc=2 且 msg 含该路径；空文件 → `ARG_EMPTY_TEXT` rc=2；两码可区分。
- E14-3 焦点不在可读控件上时 `--verify` → `ENV_TEXT_UNVERIFIABLE` rc=3（不是 `ok:true`）。
- E14-4 `--verify-mode exact`：框内已有前缀时输入不同文本 → `ENV_TEXT_NOT_ENTERED` rc=3。
- E14-5 `wclip set --native-path 'C:/a/b.txt'` → 读回 `C:\a\b.txt`。

### E15 · 定位可信（T15/T16）
- E15-1 `wshot --box 100,100,400,300` 产出的图尺寸 300×200，JSON `rect` 与请求一致，`scale==1.5`（实测环境）。
- E15-2 `--box` 越界 + 无 `--clip` → rc=2，msg 同时含正确的 W/H 与两条建议；带 `--clip` → 成功且 `clipped:true`。
- E15-3 `--rect` 空格分隔 → `ARG_BAD_RECT` rc=2（不是 `unknown arg` 静默）。
- E15-4 `ops/map --text` 在 `uiawnd` 夹具上列出的可操作节点数与 `wuia --find-name . --enabled` 的口径一致（差 0），编号严格按 (y,x) 递增。
- E15-5 `ops/map` 产出的 PNG 尺寸等于窗口 rect，图上框数等于 `actionable` 节点数。

### C14 · 窗口族（T13）
- C14-1 主窗 + 子对话框（Owner）夹具：用主窗 hwnd `--expect-hwnd` 点子对话框内按钮，带 `--allow-related` → ok 且 `matched:"related"`。
- C14-2 同一场景不带 `--allow-related` → 仍 `ENV_WINDOW_MISMATCH`（默认严格不变 = S10）。
- C14-3 无关窗口 → 带 `--allow-related` 也 `ENV_WINDOW_MISMATCH`，且 JSON `hit.title` 非空。

### C15 · wshot 契约（T15）
- C15-1 `--box`/`--rect` 互斥 → rc=2。
- C15-2 `--hwnd` 与 `--box` 互斥 → rc=2。
- C15-3 JSON 字段 `scale` 与 `screen.dpi/96` 一致（±0.01）。

## 6 · 风险与回退

- 风险 R1：去掉 `ShowWindow` 后，某些窗口无法被 `SetForegroundWindow` 激活（Win11 前台锁）。回退：保留 `ShowWindow(SW_SHOWNOACTIVATE=4)` 作为「仅当未最小化且激活失败」的末位重试，仍不改变最大化状态（`SW_SHOWNOACTIVATE` 对最大化窗口无状态影响，需 m13 实测确认）。
- 风险 R2：`--allow-related` 放宽后可能点到同族里错误的子窗。缓解：仍要求点坐标处的 hwnd 属于目标族；JSON 明确 `matched`；默认关。
